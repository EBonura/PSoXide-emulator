# Bounded submitted hardware candidate evidence

This diagnostic is opt-in: `--trace-failures --trace-checkpoint hazard-spawn --trace-hw-roi 112,80,52,260`. The ROI is an inclusive native VRAM rectangle derived from x,y,width,height, rather than display coordinates. The example covers both framebuffer halves around the HL points. It records bounding-box candidate packets, not hardware winners or a pixel-coverage oracle. No shader, comparator, mask or golden policy changes.

Only the highest requested hardware scale records this additional evidence. The renderer captures the exact TranslatedFrame before upload: translated positions, colours, UVs, flags, texture window and all 16 plane words, actual draw runs including clip and blend state, and each originating raw GP0 packet's actual translator vertex range. Context includes tick, reboot epoch and increasing segment sequence. Packet spans are captured only when explicitly enabled; normal rendering keeps the existing upload/draw path.

The renderer's texture_words array is the actual hardware sampler source, synchronized before each tick and updated by every upload/copy as the segment stream executes. Immediately before draw submission, the diagnostic copies only requested candidates' full physical texture pages and CLUT rows. Each region includes exact wrapped VRAM coordinates and dimensions. A submitted candidate may not win the target pixel. These bytes cannot establish ownership of a hardware fragment.

Limits: 4 MiB recent serialized segments per active scale; 256 ROI packet spans per segment; at most 128 raw words and 96 vertices per span; at most 16 deduplicated sampler regions and 512 KiB region data per segment. Oversize spans, missing regions and recent-window evictions set explicit truncation. Truncation means omitted candidates or texture coverage remain unknown. Two explicitly selected checkpoints per journey may export additional hardware traces. No full 16-checkpoint diagnostic matrix.

Files: hw-submitted.bin and hw-submitted-receipt.toml alongside the existing trace files. The additional receipt hashes submitted bytes, raw trace packets and the complete original trace receipt, which binds tool, disc, journey and source/map metadata. The embedded per-span raw packet is authoritative if the separate recent GP0 window has evicted that tick. Reboot epochs distinguish repeated command indices. Hardware winner verification is explicitly false.

Binary schema 1 is little endian, header PXHWSV1 followed by NUL and u32 frame count; each frame has u32 byte count and bytes. Frame: u64 tick, u32 epoch, u64 segment sequence, u32 scale, four u16 ROI edges, u32 packet-span count. Span: u32 raw GP0 index, u32 FIFO word count and words, six i32 draw-env values, u32 original submitted start/end vertex indices, then end-start vertices, u32 run count and runs. Vertex is i16 XY, four u8 colour channels, two u16 UVs, u32 flags, u32 texture window and sixteen u32 planes. Run is u32 blend enum/start/count and four u16 clip edges. Frame tail is u32 region-truncation flag, u32 region count; each region has four u16 x/y/width/height values and width*height u16 sampler words. Runs retain original global submitted ranges, so consumers must intersect them with each packet span.
